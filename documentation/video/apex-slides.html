The confidence gate

app/ml/inference.py
# 4-6. Entropy gate (precedence) → confidence gate → accepted band.
h_bits = _entropy_bits(proba)
if h_bits > th.entropy_ambiguous_bits:
    state = ConfidenceState.AMBIGUOUS
    top_prediction = None
    ledger.record(code=ErrorCode.AMBIGUOUS, entity_id=circuit,
                  detail=f"entropy {h_bits:.3f} > {th.entropy_ambiguous_bits} bits")
elif confidence < th.confidence_gate:
    state = ConfidenceState.LOW_CONFIDENCE
    top_prediction = None
    ledger.record(code=ErrorCode.LOW_CONFIDENCE, entity_id=circuit,
                  detail=f"max-prob {confidence:.4f} < gate {th.confidence_gate}")
else:
    top_prediction = drivers[int(order[0])]
    state = ConfidenceState.HIGH if confidence >= cfg.confidence_high else ConfidenceState.MEDIUM

The refusal is a served value, not an exception: the gate sets a typed state, logs its reason with the exact margin, and top_prediction stays None. The purple card in the demo is these six lines reaching the screen.

Appendix · the heart of the code · II

The leakage tripwire

app/pipeline/normalise.py
def _assert_no_leakage(train: pd.DataFrame, config: AppConfig) -> None:
    """Fail loud if any held-out circuit survives into the training set."""
    held_out = set(config.held_out_circuits)          # Belgium, Italy — quarantined from day one
    leaked = held_out & set(train["circuit"].unique())
    if leaked:
        raise NormalisationError(
            f"held-out circuits leaked into a fit: {sorted(leaked)}")
# Called inside fit_normaliser AFTER the exclusion filter — it fires only if the
# filter logic itself is broken. No artefact is written on a poisoned run.

Every fit site in the system re-asserts the train/held-out boundary independently. The held-out results earlier are only meaningful because this line can fire — and is tested to.

non-negotiable #2a single filter bug cannot silently poison an artefact

Appendix · the heart of the code · III

The deviation score

app/monitoring/detector.py
def _cosine_distance(x, b):
    """(1 − cos(x, b), per-feature ½(x̂ᵢ − b̂ᵢ)² terms) — exact additive decomposition."""
    xn, bn = norm(x), norm(b)
    if not (isfinite(xn) and isfinite(bn)) or xn == 0.0 or bn == 0.0:
        return nan, None                      # the DISTANCE_NAN path — coded, never swallowed
    d = 1.0 - dot(x, b) / (xn * bn)
    terms = 0.5 * (x/xn - b/bn) ** 2          # unit-vector identity: 1 − cos = ½‖x̂ − b̂‖²
    return d, terms

The monitor's score is a cosine distance — the shape of the behaviour, not its magnitude — and the identity on the highlighted line makes the per-feature attribution exact: the terms sum to the score. The feature chips on the alert banner are these terms, not an estimate.
